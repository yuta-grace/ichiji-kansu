## 1. 目的

公式や解法を覚えて解くことではなく、**数学の概念がなぜ成り立つかを理解し、それを使って問題を解けるようになること**を目指す。

育てたい力：
- 概念がなぜ成立するのかを理解する
- 異なる概念同士の関係に気づく
- 式・表・グラフ・場面を相互に結びつける
- 自分の言葉で説明できる
- 理解した概念を別の問題に応用できる

**【決定】** 理解と問題演習は対立させない。最終的に**補助なしで問題が解けるようになること**をゴールとする。

**【根拠】** 概念の理解と手順の習得は、片方が育つともう片方も育つ双方向の関係にある（Rittle-Johnson らの研究）。

## 2. 対象と利用場面

- **対象**：数学が苦手〜普通の中学生（得意な生徒への対応は後の段階で検討）
- **利用場面**：個別指導塾。講師がもう一人の生徒を見ている間に、生徒が一人で進める想定
- **使う端末**：生徒のスマートフォン（縦向き・指操作）と Mac（マウス・トラックパッド・キーボード）。タブレットは想定しない
- **最初の分野**：一次関数

### この分野で観察されているつまずき（開発者の指導経験より）

- 傾き・切片が式のどこにあたるかを、覚えているかいないかで分かれる
- 覚えていても、座標上でどう表れるかを考えられない
- 逆に、グラフでは分かっていても式にすると分からない
- 2点が与えられると、連立方程式しか方法がないと思っている

**【仮説】** 共通の原因は、a と b を式の「位置」で覚えていて、「意味」（a＝x が1増えたときの y の増え方、b＝x が0のときの y）で捉えていないこと。

## 3. 設計原則

1. **意味を先に体験させ、名前は後でつける。**
   【根拠】生徒が共通点や違いを自分で探した後に説明を受けると、最初から説明を受けるより理解が深まる（Schwartz & Bransford, 1998）。
2. **表現の行き来は必ず両方向で扱う。** 式→グラフ、グラフ→式、表→式。
3. **ヒントは答えではなく、小さな段階に分けた問いとして出す。** 各段階で生徒に答えさせる。
4. **補助は外すためにある。** 正解が続いたら減らし、つまずいたら戻す。
   【根拠】支援を段階的に減らす方法の効果（Renkl らの研究）。
5. **ヒントを使っても不利にならない。** 減点や問題追加はしない。
6. **解き方は1つに決めない。** 同じ答えに至る複数の解き方を使い分けられることを目指す。
   【根拠】複数の解き方を比べることが、解き方を柔軟に選ぶ力を育てる（Star & Rittle-Johnson らの研究）。
7. **装飾はシンプルに、数学の表現は丁寧に。**
   【根拠】学習と関係のない装飾は学習を妨げることがある（Mayer らの誘惑的詳細効果）。グラフ・表・操作できる図には手間をかける。
8. **入口で設定や世界観を説明しない。** 最初の30秒で問いに入る。
9. **間違いに✕だけを返さない。** その答えが何を表すかを返し、生徒が自分でずれに気づけるようにする。

## 4. 博士

### 役割
| 場面 | 振る舞い |
|---|---|
| **案内役**（何から学ぶか、次に何をするか） | 全体を知っている存在として、進む道を提案する |
| **問いかけ役**（理解の場面） | 答えを言わず、生徒と一緒に考える |

### 振る舞いのルール
- 答えをすぐに教えない
- 必ず具体例から入る
- 表現を行き来させる問いを投げる
- 生徒の答えを否定せず、「その考えだと、これはどうなる？」と返す
- **関係を先に言わない。** 「これは前にやった○○と同じ形だね」のような台詞は使わない。代わりに、画面に2つを並べて「何か似ているところはある？」と問い、生徒が気づいた後で名前をつける
- 「理解」「概念」など設計側の言葉を台詞に使わない

### 台詞の作り方
- 設計書に書かれていない台詞（正解・不正解への反応、案内、診断・練習・ダンジョンの台詞）は、Claude Code が上のルールに沿って草案を作る
- 草案はプロジェクトに持ち込んで確認してから確定する
- 確定までは仮の台詞で実装してよい

### 見た目
- シンプルなアイコンと文字のみ。凝ったイラストや演出は作らない

## 5. 学習の構成

```
診断（準備運動） → 理解 → 練習 → 解法ダンジョン
```

### 5.0 進み方

- **【決定】** すべてのパートを最初から選べるようにする。順番による解放（ロック）はしない。
- 最初に博士が「一次関数、どれくらい知ってる？」と聞き、答えに応じて入口を提案する。
  - あまり知らない → 理解（説明）から
  - ある程度知っている → 練習・ダンジョン（実戦）から
- 講師が「今日はダンジョン」のように指示して、途中から入ることもできる。

### 5.1 診断（準備運動）

- 「テスト」とは呼ばない。「準備運動」として見せる
- 一次関数に必要な前提だけを短く確認する（6問）
  - 比例 2問（例：y = 2x で x = 3 のとき y は？）
  - 負の数の計算 2問（足し算・引き算を1問、かけ算を1問）
  - 文字式に数を代入する 1問（負の数を代入する）
  - 簡単な分数の計算 1問
  - 数の範囲は −10〜10 程度。問題は Claude Code が草案を作り、プロジェクトで確認する
- 易しい問題から出す
- 「小5レベル」など学年や水準を表示しない
- **【決定】** 最初の版では、結果は**記録するだけ**で、他の機能には影響させない。つまずきがあった場合は博士が「ここは後で一緒に確認しよう」と伝えて先に進む

### 5.2 理解（水そうの場面）

約7分。紙の台本で講師が行っている流れをアプリにしたもの。

1. **場面**：博士「水そうに最初から水が4L入っている。そこに毎分2Lずつ水を入れるよ」
2. **表を埋める**：0〜4分の水の量を入力
3. **予想**：「この5つをグラフに点で打ったら、どんな並び方になると思う？」
   - 選択肢（4つ）：「まっすぐ並ぶ」「だんだん急になる」「だんだんゆるやかになる」「バラバラ」
   - 間違った選択肢を選んでも直さず、そのまま次へ進む。点を打った後に博士が「予想と比べてどうだった？」と聞く。**予想と結果のずれに気づくこと自体が目的**
4. **点を打つ**：グラフ上をタップして5点を打つ
5. **グラフの中で探す**
   - 「最初の4Lは、グラフのどこに見える？」→ 該当する点をタップ
   - 「毎分2Lずつ増えるのは、グラフだとどう見える？」→ 点から点へ「右に1、上に2」の階段を表示して確かめる
6. **1つだけ変える**：「毎分3Lにしたら？」「最初が0Lだったら？」
   - 予想は選択式：「急になる」「ゆるやかになる」「上にずれる」「下にずれる」
   - 予想の後、**元のグラフを薄く残したまま**新しいグラフを重ねて表示する
7. **式にする**：「12分後は何L？表を12分まで書かずに求められる？」→ 式 y = 2x + 4 を作る（a と b を入力）
   - 作れないときのヒント（段階）：
     1. 1分で2L増えるなら、12分では何L増える？
     2. 最初の4Lを足すと？
     3. x 分だったら？
8. **名前をつける**：「式の2はグラフのどこにあった？4は？」の後で、博士が「この2を『傾き』、4を『切片』って呼ぶんだ」と伝える
9. **逆向き**：場面のないグラフを**1問**だけ見せる（例：y = 3x + 1 の直線）。**式は見せず、グラフだけ**を見せる。直線は格子点をはっきり通るものにする。x = 0 のときの値と増え方を読み、式を作る

#### 理解パートで間違えたときの返し方（共通）
1. **1回目**：✕を出さず、その答えが何を表すかを返す
   - 例：打った点の座標を表示し、「この点は何分のとき、何L？」と聞く
   - 例：表の値が違う → 「0分のとき、水そうには何L入っている？」
2. **2回目**：手がかりを指す（例：表の該当する列を光らせる）
3. **3回目**：正しい答えを見せて先へ進む

### 5.3 練習

3方向の問題を混ぜて出す。

| 種類 | 内容 | 入力 |
|---|---|---|
| 式 → グラフ | y = 3x − 2 のグラフを描く | 直線上の2点をタップ |
| グラフ → 式 | 描かれた直線の式を求める | a と b を入力 |
| 表 → 式 | x と y の表から式を求める | a と b を入力 |

**問題の範囲**
- **9問**（3方向 × 3問）を混ぜて出し、9問で終了する。ダンジョンへ進む条件はつけない
- 傾きは整数。後半に負の数を含める
- 分数の傾きは、表→式の最後に1問だけ
- 切片は必ずグラフの表示範囲内に入れる

**問いの言葉**
- 生徒はすでに「傾き」「切片」を知っている前提で「傾きは？」「切片は？」と聞く
- **最初の数回と、間違えたときだけ**注釈を出す：「傾き（x が1増えると y がいくつ増えるか）」「切片（x が0のときの y）」
- 注釈は、**3方向まとめて**3問連続正解で消す。間違えたら再表示し、また3問から数え直す

**ヒント（段階）**
1. x が0のとき、y はいくつ？
2. x が1増えると、y はいくつ増える？
3. この2つを式に入れると？

**ヒントの出し方**
- 最初の版は、**生徒がヒントボタンを押したときだけ**出す
- 例外：2回間違えたら、博士が「ヒントを見てみる？」と声をかける（自動では出さない）

### 5.4 解法ダンジョン：2点から直線の式を求める

#### 3つの解き方
| 番号 | 生徒に見せる名前【仮】 | 解き方 | 向いている問題 | 例 |
|---|---|---|---|---|
| ① | 連立で解く | 連立方程式 | 座標が大きい・複雑 | (12, 7) と (−9, 21) |
| ② | 代入で解く | 傾きを求めて、点を代入して方程式で切片を求める | 傾きが分数 | (2, 1) と (5, 3) |
| ③ | 戻って解く | 傾きを求めて、x = 0 まで戻して切片を見積もる | 傾きが整数で、x = 0 に戻しやすい | (1, 5) と (3, 9) |

- 名前は仮。データとして持ち、後から変えられるようにする
- **【決定】** どの解き方でも解けるが、問題によって楽な方法が違う問題を混ぜて出す

#### 解き方の導入（初めてダンジョンに入ったとき）
1. **③を最初に、問いの形で体験させる。** 理解パートの「最初（x = 0）まで戻る」考え方の延長として、段階的な問いでたどらせる：
   1. 2つの点をグラフに打ってみよう
   2. x が1から3まで増えたとき、y はいくつ増えた？
   3. では、x が1増えると、y はいくつ増える？
   4. x を1から0に戻すと、y はいくつになる？
   5. 式にすると？
   - 解けた後で、博士が「このやり方を『戻って解く』と呼ぼう」と名前をつける
2. **②は、③が面倒になる問題で見せる。** 傾きが分数の問題で③を試すと計算が大変になる。そこで博士が「別のやり方もあるよ」と②の手順を例として見せる
3. **①は教えない。** 生徒はすでに知っているので、選んだら「それも1つのやり方だね」と認めるだけ

#### 補助の段階
**解き方は、段階A・Bのどちらでも先に選ぶ。** どの段階を出すかは、**選んだ解き方の段階**で決まる（例：③が段階Bでも、①を選べば①の段階Aになる）。

**段階A（補助つき）**：解き方を選び、その解き方の途中の値を答えてから、a と b を答える。

| 解き方 | 答えさせる途中の値 | 正解の扱い |
|---|---|---|
| ① 連立で解く | 2つの式を引いてできる「○a = ○」の2つの数 | どちらの順に引いても正解 |
| ② 代入で解く | 傾き、代入する点の x と y | どちらの点を代入しても正解 |
| ③ 戻って解く | 傾き、「x = 0 まで x はいくつ変わる？」「そのとき y はいくつ変わる？」 | **符号つき**で答える。どちらの点から戻っても正解 |

**段階B（補助なし）**：解き方を選び、答え（a と b）だけを入力する。

**切り替えルール（初期値）**
- その解き方で段階Aを3問続けて正解 → その解き方は段階Bへ
- 段階Bで間違えたら、その解き方は次の1問だけ段階Aに戻る

**注意**：段階Bでは、選んだ解き方を本当に使ったかは確かめられない。これは受け入れる。

#### 解き方の選び方
- 基本は生徒が自由に選ぶ
- 導入（上記）と解き比べのときだけ、博士が解き方を指定する

#### 解き比べ
- 2つの解き方が「使える」になったら、博士が解き比べを提案する（生徒は断ってもよい）
- 比べるのは、その2つの解き方
- 両方とも段階Bの形（解き方を選ぶ＋答えだけ）で解き、それぞれの時間を本人に見せる。**この時間は称号のタイムとは別扱い**
- 「どっちが楽だった？」と問う
- 連立方程式を否定しない。同じ答えに至る道が複数あることに気づかせる

#### マスター称号
解き方ごとに称号を与える（例：「戻って解くマスター」）。条件は2段階＋タイム。

1. **使える**：その解き方で、段階Aで3問正解。3問の中に**傾きが正の問題と負の問題の両方**を含む
2. **使い分けられる**：段階Bで、その問題の「最も楽な解き方」としてその解き方を選んで正解（3問）、または解き比べを1回行う
3. **タイム**：段階Bで、その解き方の本人の最初の段階B記録より速く解けた

タイムのルール：
- 正確に解けるようになってから計る。段階Aは計測しない
- 決まった基準ではなく、**本人の過去の記録と比べる**
- 解いている最中にタイマーを目立たせない（結果画面で見せる）

#### 問題の用意
- **【決定】** 最初の版は**固定の問題集**とする
- Claude Code が草案を作る：各解き方が「最も楽な解き方」になる問題を10問ずつ、計30問程度
- 各問題に「最も楽な解き方」のタグをつけ、**タグはプロジェクトで確認する**
- 2点はすべて整数座標にする

### 5.5 間違えたときの共通の扱い（練習・ダンジョン）

1. **1回目**：もう一度答えさせる。a と b のどちらが違うかだけ示す
2. **2回目**：博士が「ヒントを見てみる？」と声をかける（自動では出さない）
3. ヒントを最後まで使っても違ったら、解き方を順に見せて次の問題へ進む
4. 見せた問題と同じ種類の問題を、**後でもう一度出す**（問題を追加するのではなく、出題順の調整で行う）

## 6. 入力の仕様

### 数字入力
- 答えは y = ax + b の **a と b を別々に入力**する（どちらを間違えたか分かるように）
- 負の数と分数を入力できること
- スマートフォンでは指で入力しやすいこと。Mac では物理キーボードでも入力できること

### 答えの判定
- **約分していない分数**（例：4/6）：正解として扱い、博士が「約分すると？」と聞く
- **小数**（例：0.5）：同じ値なら受け付ける
- **帯分数**：使わない

### グラフへの点の打ち込み
- **【決定】座標は整数の点（格子点）のみ。** 分数や小数の座標を打たせる問題は出さない
- タップした位置から一番近い格子点に吸着させる
- 指で打ちやすいように、格子の間隔とタップの判定範囲を十分にとる
- 打った点は取り消し・移動できること
- 問題に使う2点もすべて整数座標にする（傾きが分数になる問題でも、点の座標は整数）

## 8. 最初の版の範囲

### 作るもの
| 要素 | 内容 |
|---|---|
| 診断（準備運動） | 一次関数の前提を6問 |
| 理解 | 水そうの場面を1つ |
| 練習 | 3方向9問、段階的ヒント、注釈の出し分け |

### 段階4の作業中に仮に決めたこと（Claude Code・2026-11-04）
**理解パートの修正に伴うもの**（台詞は `src/content/understanding.json`。下の台詞は草案）
- **「実際はどう並んでた？」で違うものを選んだとき**（確定済み）：共通の3段階で返す
  - 1回目：選んだものごとに、その並び方なら上がり方がどうなるはずかを返す（例：「だんだん急になるなら、点から点への上がり方が、だんだん大きくなっていくはずだね。上がり方を見比べてみよう。」）

- **「ほかの点から点も同じかな？」の後**：「同じ」「ちがう」のどちらを選んでも、「全部の点から点に、階段を出してみたよ。」と言って全部の階段を表示する。「ちがう」を選んだ生徒に追加の問いはしない

**診断（準備運動）**（6問・「わからない」ボタン・正しい答えを見せないことは 9章のとおり確定。以下は仮）

- **最初と最後**：最初の問題の前に「準備運動、6問いくよ。」。最後は「準備運動おわり。」の後、入口の答えに応じて次を提案する。何問できたかは表示しない
- **記録**：問題ごとに 正解／誤答（入力した数）／わからない と時間を残す

**練習**（問題と台詞は `src/content/practice.json`。9章で確定したもの以外は草案）
- **9問と出題順**：①式→グラフ y = 2x + 1、②グラフ→式 y = x + 3、③表→式 y = 3x − 1（x = 0, 1, 2, 3）、④式→グラフ y = 3x − 2、⑤グラフ→式 y = −2x + 3、⑥式→グラフ y = −x + 4、⑦表→式 y = −2x + 5（x = 1, 2, 3, 4）、⑧グラフ→式 y = −3x + 2、⑨表→式 y = 2/3 x + 1（x = 0, 3, 6, 9）
- **グラフの範囲**：x、y とも −5〜5
- **式→グラフ**：点はちょうど2つ打つ。違ったときは、打った2点を通る線を引いて見せ、「傾き／切片がちがうみたい」と返す
- **ヒントの順番**：①〜⑥・⑧は「x が 0 のとき」→「x が 1 増えると」→「この2つを式に入れると？」。⑦は「x が 1 増えると」→「x を1から0に戻すと」→最後。⑨は「x が 0 のとき」→「x が0から3に増えると」→「x が3増えて y が2増えるなら、x が 1 増えると」→最後
- **ヒントの問いで間違えたときの返し方（1回目）**：x = 0 のときの y を間違えたら、その y になるのは x がいくつのときかを返す（x が整数にならないときは「y が○になるところを、もう一度見てみよう。x は 0 になっている？」）。増え方を間違えたら、その増え方だと次の x で y がいくつになるはずかを返す。式→グラフでは「式の x に 0（1）を入れて確かめてみよう」
- **ヒントの手がかり（2回目）**：x = 0 の縦の線・表の列を光らせる、「右に○」の線を引く、「2を3つに分けると？」など
- **わかったこと**：ヒントで答えた値は「わかったこと」の欄に残し、元の問題に戻っても見えるようにする
- **解き方の見せ方**：「x が 0 のとき、y は○。だから切片は○。」→「x が 1 増えると、y は○増える（○減る。○減るから、傾きは−○）。」→「式にすると、y ＝ ○。」を1つずつ出す
- **「同じ種類」**：3方向のどれかで判断する。まだ出していない同じ種類の問題を、間に1問はさむ位置まで前に寄せる。残っていなければ何もしない
- **約分していない分数**：「約分すると？」と聞き、次の答えが何であっても正解として扱う
- **最初と最後**：最初に「練習、9問いくよ。」。最後は「練習おわり。次は、解法ダンジョンに行ってみよう。」。何問できたかは表示しない

**解法ダンジョン**（問題・台詞は `src/content/dungeon.json`。9章で確定したもの以外は草案）
- **問題集**：③向き10問・②向き10問（うち6問は切片が分数）・①向き10問を順に混ぜて並べ、最後まで行ったら最初に戻る。best タグ：③向きは ["modoru"]、切片が分数の②向きは ["dainyu"]、切片が整数の②向きは ["dainyu", "modoru"]、①向きは ["renritsu"]
- **段階Bのヒント**：段階Aと同じ途中の問いを、ヒントとして順にたどる。最後まで答えたら元の問題に戻る
- **③で戻す点**：どちらの点から戻ってもよい。生徒が答えた x の変わり方で、次の「y はいくつ変わる？」の答えが決まる
- **①を初めて選んだとき**：「それも1つのやり方だね。」と一度だけ言う
- **解き方のボタン**：解き方の名前の横に「途中も答える／答えだけ」を小さく出す
- **時間**：段階Bで正解したときだけ、結果で「かかった時間」を見せる。2回目からは「最初の記録」も並べる。「最初の記録」は段階Bで最初に正解したときの時間
- **解き比べ**：2つの解き方が「使える」になった後、問題を1つ解き終えたところで勧める。断ったら、次にダンジョンに入るまで勧めない。問題は、比べる2つのどちらかが best タグにある問題を次の問題から探す（称号には使わないので、タグをここで使っている）
- **グラフ**：2点と切片が −10〜10 に収まる問題だけ、2点をグラフに出す
- **「他のやり方」に出す解き方**：導入を済ませた解き方だけ（②の導入前に②の手順を見せないため）。①はいつも出す
- **「他のやり方」を聞く条件**：解き方を見せずに正解にたどりついたとき（途中で間違えて直した場合も含む）。解き比べの問題では聞かない
- **「あとで聞く」（ダンジョン）**：解いている途中に押したときは、そのとき使っていた解き方と一緒に残す。一覧から「見る」を押すと、その問題の数字でその解き方の手順を1つずつ見せる（最後に「わからないところは先生に聞いてみよう」）
- **ホームでの提案**：アプリを開いた後、そのニックネームで最初にホームを出したときに1回だけ。開く前に残したもののうち、いちばん古いもの1件

**練習の「あとで聞く」**（草案）
- 解いている途中（ヒントの途中も含む）に押せる。一度押すと、その問題ではボタンが消え、続けて解ける
- 一覧の見出しは「練習：y ＝ 2x ＋ 1」（式→グラフ）、「練習：グラフから式」「練習：表から式」
- 一覧から「見る」を押すと、問題（式・グラフ・表）を出したまま、練習の解き方の説明を1つずつ見せる

**講師用の暗証番号**（草案）
- 忘れたときに作り直す方法はない（ブラウザのサイトデータを消すと作り直せるが、すべての記録も消える）

**ニックネーム**（文言は `src/content/profile.json`。草案）
- 12文字まで。同じ名前は作れない
- アプリを開くたびに選ぶ画面を出す。前回のニックネームを「○○で続ける」として大きく出し、ほかの人の名前と「新しく作る」を並べる。ホームの「人を変える」でも選び直せる
- 講師用画面で削除するときは確認を出す。削除したニックネームを選んでいたら、選ぶ画面に戻る

**端末**
- 幅375px・高さ553px（iPhone SE 第2・3世代でブラウザのバーが出ている状態）では、グラフ→式の問題でキーパッドを開くとグラフの高さが約155pxまで小さくなる（閉じれば約250〜310px）
- 幅320pxの古い小さな iPhone（初代 SE）では、点を打つ画面のグラフが小さくなる。最小の想定は幅360〜375px とした

## 11. Claude Code への依頼

- この設計書の8章「作るもの」を実装する
- Webアプリとして、スマートフォン（縦向き・指操作）と Mac の両方で使えるようにする
- 技術選定は任せる。ただし次を守る
  - ログインなし、個人情報を保存しない、進み具合は端末内に保存
  - 問題・ヒント・博士の台詞・解き方の名前はコードと分けて、後から編集しやすいデータとして持つ
  - 補助の切り替えや称号の条件の数値は、後から変更しやすくする
- 判断が必要な点が出たときは、0章のルールに従う（影響の大きいものは事前に質問、細かいものは仮実装して10章に追記）
- 段階3（理解パート）が終わった時点で一度報告する
