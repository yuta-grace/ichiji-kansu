## 1. 目的

公式や解法を覚えて解くことではなく、**数学の概念がなぜ成り立つかを理解し、それを使って問題を解けるようになること**を目指す。

育てたい力：
- 概念がなぜ成立するのかを理解する
- 異なる概念同士の関係に気づく
- 式・表・グラフ・場面を相互に結びつける
- 自分の言葉で説明できる
- 理解した概念を別の問題に応用できる

**【決定】** 理解と問題演習は対立させない。最終的に**補助なしで問題が解けるようになること**をゴールとする。

**【根拠】** 概念の理解と手順の習得は、片方が育つともう片方も育つ双方向の関係にある（Rittle-Johnson らの研究）。

## 2. 対象と利用場面

- **対象**：数学が苦手〜普通の中学生（得意な生徒への対応は後の段階で検討）
- **利用場面**：個別指導塾。講師がもう一人の生徒を見ている間に、生徒が一人で進める想定
- **使う端末**：生徒のスマートフォン（縦向き・指操作）と Mac（マウス・トラックパッド・キーボード）。タブレットは想定しない
- **最初の分野**：一次関数

### この分野で観察されているつまずき（開発者の指導経験より）

- 傾き・切片が式のどこにあたるかを、覚えているかいないかで分かれる
- 覚えていても、座標上でどう表れるかを考えられない
- 逆に、グラフでは分かっていても式にすると分からない
- 2点が与えられると、連立方程式しか方法がないと思っている

**【仮説】** 共通の原因は、a と b を式の「位置」で覚えていて、「意味」（a＝x が1増えたときの y の増え方、b＝x が0のときの y）で捉えていないこと。

## 3. 設計原則

1. **意味を先に体験させ、名前は後でつける。**
   【根拠】生徒が共通点や違いを自分で探した後に説明を受けると、最初から説明を受けるより理解が深まる（Schwartz & Bransford, 1998）。
2. **表現の行き来は必ず両方向で扱う。** 式→グラフ、グラフ→式、表→式。
3. **ヒントは答えではなく、小さな段階に分けた問いとして出す。** 各段階で生徒に答えさせる。
4. **補助は外すためにある。** 正解が続いたら減らし、つまずいたら戻す。
   【根拠】支援を段階的に減らす方法の効果（Renkl らの研究）。
5. **ヒントを使っても不利にならない。** 減点や問題追加はしない。
6. **解き方は1つに決めない。** 同じ答えに至る複数の解き方を使い分けられることを目指す。
   【根拠】複数の解き方を比べることが、解き方を柔軟に選ぶ力を育てる（Star & Rittle-Johnson らの研究）。
7. **装飾はシンプルに、数学の表現は丁寧に。**
   【根拠】学習と関係のない装飾は学習を妨げることがある（Mayer らの誘惑的詳細効果）。グラフ・表・操作できる図には手間をかける。
8. **入口で設定や世界観を説明しない。** 最初の30秒で問いに入る。
9. **間違いに✕だけを返さない。** その答えが何を表すかを返し、生徒が自分でずれに気づけるようにする。

## 4. 博士

### 役割
| 場面 | 振る舞い |
|---|---|
| **案内役**（何から学ぶか、次に何をするか） | 全体を知っている存在として、進む道を提案する |
| **問いかけ役**（理解の場面） | 答えを言わず、生徒と一緒に考える |

### 振る舞いのルール
- 答えをすぐに教えない
- 必ず具体例から入る
- 表現を行き来させる問いを投げる
- 生徒の答えを否定せず、「その考えだと、これはどうなる？」と返す
- **関係を先に言わない。** 「これは前にやった○○と同じ形だね」のような台詞は使わない。代わりに、画面に2つを並べて「何か似ているところはある？」と問い、生徒が気づいた後で名前をつける
- 「理解」「概念」など設計側の言葉を台詞に使わない

### 台詞の作り方
- 設計書に書かれていない台詞（正解・不正解への反応、案内、診断・練習・ダンジョンの台詞）は、Claude Code が上のルールに沿って草案を作る
- 草案はプロジェクトに持ち込んで確認してから確定する
- 確定までは仮の台詞で実装してよい

### 見た目
- シンプルなアイコンと文字のみ。凝ったイラストや演出は作らない

## 5. 学習の構成

**【決定】（2026-11-05）** 画面の下に3つのタブを置く：**学ぶ／ノート／後で聞く**。問題を解いている間はタブを隠し、問題に集中できるようにする。

**学ぶ（ホーム）** には、上から次の順に並べる。
1. 博士の一言（「後で聞く」の提案など。1行程度）
2. 大きな「続きから」カード（入口の区分・名前と「○問目から始める」ボタン）
3. 入口の一覧（進み具合つき）

| まとまり | 区分 | 入口の名前 | 内容 |
|---|---|---|---|
| はじめに | — | 準備運動 | 5.1 |
| はじめに | — | 仕組みを知る（水槽） | 5.2（旧「水そうの話」） |
| 問題を解く | 基本 | 傾きと切片を読む | 5.3（旧「練習」） |
| 問題を解く | 標準 | 2点から式を作る | 5.4（旧「解法ダンジョン」） |
| 問題を解く | 標準 | 交点と直線上の点 | 5.6（新規） |
| 問題を解く | 発展 | 座標と図形 | 5.7（新規） |
| 問題を解く | 生活 | 暮らしの中の一次関数 | 5.8（新規） |
| ミックス | — | ミックス | 5.9（新規） |

- 区分（基本・標準・発展・生活）は小さなラベルで表示する。「最難関」などの言葉は使わない
- 「解法ダンジョン」「ダンジョン」という言葉は画面に出さない
- 「あとで聞く」は「後で聞く」と書く
- **漢字**：対象は中学生以上なので、台詞・ボタン・表示は常識の範囲で漢字を使う（続きから、始める、答える、仕組み、水槽、昨日、付ける、切り替え、薄く など）。中学生が読めない難しい漢字は使わない
- **目標**：都立高校入試の関数の問題が解けるところまで。ただし今は一次関数（中2の範囲）だけで作る

### 5.0 進み方

- **【決定】** すべての入口を最初から選べるようにする。順番による解放（ロック）はしない。
- 最初に博士が「一次関数、どれくらい知ってる？」と聞き、答えに応じて入口を提案する。
  - あまり知らない → 仕組みを知る（水槽）から
  - ある程度知っている → 問題を解く（傾きと切片を読む・2点から式を作る）から
- 講師が「今日は2点から式を作る」のように指示して、途中から入ることもできる。

### 5.1 診断（準備運動）

- 「テスト」とは呼ばない。「準備運動」として見せる
- 一次関数に必要な前提だけを短く確認する（6問）
  - 比例 2問（例：y = 2x で x = 3 のとき y は？）
  - 負の数の計算 2問（足し算・引き算を1問、かけ算を1問）
  - 文字式に数を代入する 1問（負の数を代入する）
  - 簡単な分数の計算 1問
  - 数の範囲は −10〜10 程度。問題は Claude Code が草案を作り、プロジェクトで確認する
- 易しい問題から出す
- 「小5レベル」など学年や水準を表示しない
- **【決定】** 最初の版では、結果は**記録するだけ**で、他の機能には影響させない。つまずきがあった場合は博士が「ここは後で一緒に確認しよう」と伝えて先に進む

### 5.2 仕組みを知る（水槽）（旧「水そうの話」）

約7分。紙の台本で講師が行っている流れをアプリにしたもの。

1. **場面**：博士「水そうに最初から水が4L入っている。そこに毎分2Lずつ水を入れるよ」
2. **表を埋める**：0〜4分の水の量を入力
3. **予想**：「この5つをグラフに点で打ったら、どんな並び方になると思う？」
   - 選択肢（4つ）：「まっすぐ並ぶ」「だんだん急になる」「だんだんゆるやかになる」「バラバラ」
   - 間違った選択肢を選んでも直さず、そのまま次へ進む。点を打った後に博士が「予想と比べてどうだった？」と聞く。**予想と結果のずれに気づくこと自体が目的**
4. **点を打つ**：グラフ上をタップして5点を打つ
5. **グラフの中で探す**
   - 「最初の4Lは、グラフのどこに見える？」→ 該当する点をタップ
   - 「毎分2Lずつ増えるのは、グラフだとどう見える？」→ 点から点へ「右に1、上に2」の階段を表示して確かめる
6. **1つだけ変える**：「毎分3Lにしたら？」「最初が0Lだったら？」
   - 予想は選択式：「急になる」「ゆるやかになる」「上にずれる」「下にずれる」
   - 予想の後、**元のグラフを薄く残したまま**新しいグラフを重ねて表示する
7. **式にする**：「12分後は何L？表を12分まで書かずに求められる？」→ 式 y = 2x + 4 を作る（a と b を入力）
   - 作れないときのヒント（段階）：
     1. 1分で2L増えるなら、12分では何L増える？
     2. 最初の4Lを足すと？
     3. x 分だったら？
8. **名前をつける**：「式の2はグラフのどこにあった？4は？」の後で、博士が「この2を『傾き』、4を『切片』って呼ぶんだ」と伝える
9. **逆向き**：場面のないグラフを**1問**だけ見せる（例：y = 3x + 1 の直線）。**式は見せず、グラフだけ**を見せる。直線は格子点をはっきり通るものにする。x = 0 のときの値と増え方を読み、式を作る

#### 理解パートで間違えたときの返し方（共通）
1. **1回目**：✕を出さず、その答えが何を表すかを返す
   - 例：打った点の座標を表示し、「この点は何分のとき、何L？」と聞く
   - 例：表の値が違う → 「0分のとき、水そうには何L入っている？」
2. **2回目**：手がかりを指す（例：表の該当する列を光らせる）
3. **3回目**：正しい答えを見せて先へ進む

### 5.3 基本：傾きと切片を読む（旧「練習」）

3方向の問題を混ぜて出す。

| 種類 | 内容 | 入力 |
|---|---|---|
| 式 → グラフ | y = 3x − 2 のグラフを描く | 直線上の2点をタップ |
| グラフ → 式 | 描かれた直線の式を求める | a と b を入力 |
| 表 → 式 | x と y の表から式を求める | a と b を入力 |

**問題の範囲**
- **9問**（3方向 × 3問）を混ぜて出し、9問で終了する。「2点から式を作る」へ進む条件はつけない
- 傾きは整数。後半に負の数を含める
- 分数の傾きは、表→式の最後に1問だけ
- 切片は必ずグラフの表示範囲内に入れる

**問いの言葉**
- 生徒はすでに「傾き」「切片」を知っている前提で「傾きは？」「切片は？」と聞く
- **最初の数回と、間違えたときだけ**注釈を出す：「傾き（x が1増えると y がいくつ増えるか）」「切片（x が0のときの y）」
- 注釈は、**3方向まとめて**3問連続正解で消す。間違えたら再表示し、また3問から数え直す

**ヒント（段階）**
1. x が0のとき、y はいくつ？
2. x が1増えると、y はいくつ増える？
3. この2つを式に入れると？

**ヒントの出し方**
- 最初の版は、**生徒がヒントボタンを押したときだけ**出す
- 例外：2回間違えたら、博士が「ヒントを見てみる？」と声をかける（自動では出さない）

### 5.4 標準：2点から式を作る（旧「解法ダンジョン」）

**【決定】（2026-11-05）** 解き方を問題の前に選ばせることはやめる。問題は **a と b を答えるだけ**にする。段階A・段階Bと、解き方ごとの切り替えはなくす。3つの解き方は**どれも一度は解説する**（①連立方程式も解説する）。どれを使うかは生徒次第。

#### 3つの解き方
| 番号 | 解き方 | 向いている問題 | 例 |
|---|---|---|---|
| ① | 連立方程式 | 座標が大きい・複雑 | (12, 7) と (−9, 21) |
| ② | 傾きを求めて、点を代入して方程式で切片を求める | 傾きが分数 | (2, 1) と (5, 3) |
| ③ | 傾きを求めて、x = 0 まで戻して切片を求める | 傾きが整数で、x = 0 に戻しやすい | (1, 5) と (3, 9) |

- 「戻って解く」「代入で解く」「連立で解く」という名前は使わない。名前は生徒が付ける
- **【決定】** どの解き方でも解けるが、問題によって楽な方法が違う問題を混ぜて出す（問題集は今の30問）

#### 解き方の3つの状態
1. **まだ知らない**：ノートとヒントの選択画面で、内容にもやをかけて表示し、「まだ知らない解き方・タップして学ぶ」と出す。タップすると、その解き方を例題で1つずつ学べる
2. **学んだ・名前なし**：「新しい解き方」と表示する
3. **名前あり**：生徒が付けた名前で表示する

#### 解き方を学ぶ場面
- **初めて「2点から式を作る」に入ったとき**：③を問いの形でたどる（2点を打つ → x が1から3まで増えたとき y はいくつ増えた？ → x が1増えると？ → じゃあ、x が 0 のとき、y はいくつかな？ → 式にすると？）。最後に博士が「このやり方をノートに保存したよ。名前を付けてみる？」と言う
- **②の導入**：今と同じ問題（切片が分数になる問題）で行う。③で解いた後に②の手順を例として見せ、最後は同じくノートに保存する
- **①**：5問解いても①を学んでいなければ、博士が「まだ知らない解き方があるよ。見てみる？」と1回だけ提案する
- **ノートから**：もやのかかった解き方をタップすると学べる
- **問題の途中から**：ヒントの選択画面で、もやのかかった解き方をタップすると学べる。学んだ後は元の問題に戻る

#### ノート（タブ）
- 上部で「解き方」と「称号」を切り替える
- 解き方ごとに：番号、名前（変更できる）、1〜2行の概要、「例題を見る」
- **【決定】（2026-11-05）** 解き方を使った回数は数えない（問題では a と b だけを答えるため、どの解き方を使ったかはアプリからは分からない）。正解後に「どの解き方で解いた？」とも聞かない
- 名前を付けるとき、おすすめの名前を2つほど出す（例：傾きから戻る、式に入れる、連立する）

#### ヒント
- ヒントを押したら、まず「どの解き方でヒントを見る？」と聞き、ノートの解き方から選ばせる（まだ知らない解き方はもやつきで表示）
- その後の流れ（途中の問い、間違えたときの3段階、最後は元の問題に戻る）は今と同じ

| 解き方 | ヒントで答えさせる途中の値 | 正解の扱い |
|---|---|---|
| ① | 2つの式を引いてできる「○a = ○」の2つの数 | どちらの順に引いても正解 |
| ② | 傾き、代入する点の x と y | どちらの点を代入しても正解 |
| ③ | 傾き、「x = 0 まで x はいくつ変わる？」「そのとき y はいくつ変わる？」 | **符号つき**で答える。どちらの点から戻っても正解 |

- 傾きは「見えている変化（x が○から○に増えると）→ 1あたり」の順に聞く

#### 正解した後
- 「他のやり方も見てみる？」は今のまま残す。まだ知らない解き方もここから学べるようにする

#### 記録
- ヒントで選んだ解き方と、正解後に見た解き方を、問題ごとに記録する（記録だけ。画面には出さない）

#### 問題の用意
- **【決定】** 固定の問題集（30問）。各問題の「最も楽な解き方」のタグ（best）はメモとして残す
- 2点はすべて整数座標にする

### 5.5 間違えたときの共通の扱い（問題を解く入口）

1. **1回目**：もう一度答えさせる。a と b のどちらが違うかだけ示す
2. **2回目**：博士が「ヒントを見てみる？」と声をかける（自動では出さない）
3. ヒントを最後まで使っても違ったら、解き方を順に見せて次の問題へ進む
4. 見せた問題と同じ種類の問題を、**後でもう一度出す**（問題を追加するのではなく、出題順の調整で行う）

### 5.6 標準：交点と直線上の点（新規・草案を確認してから作る）

- 10問。直線上で y（または x）が決まった点の座標を求める／2直線の交点の座標を求める／直線と x 軸・y 軸の交点
- 問題文・答え・タグ・ヒントの段階は Claude Code が草案を作り、プロジェクトで確認してから実装する

### 5.7 発展：座標と図形（新規・草案を確認してから作る）

- 10問。後半ほど難しくなるように並べる
  - 2直線と軸で囲まれた三角形の面積
  - 動く点：長方形などの辺の上を、点Pが毎秒○cmで動くとき、x秒後の三角形の面積 y を x の式で表す、など。速さ・時間・道のりの関係を使う問題
- 答え方の形が今と違う問題（座標・面積・動く点の図など）は、画面の案を出して確認してから実装する

### 5.8 生活：暮らしの中の一次関数（新規・草案を確認してから作る）

- 10問。料金（基本料金＋使った量）、水量、速さ・道のり、ろうそくの長さなど

**5.6〜5.8 共通**：問題はすべてオリジナルで作る。市販の問題集や入試問題をそのまま使わない。

### 5.9 ミックス（新規）

- 生徒が1問以上解いたことのある入口から、問題を混ぜて10問出す
- 同じ種類が続かないように並べる
- 解き方ノートやヒントの仕組みはそのまま使う

### 5.10 称号

**【決定】（2026-11-05）** 「使える／慣れた／タイム」はなくし、次の2種類にする。

1. **解いた数**：入口ごとに、正解した問題の数で段階的に（例：10問、30問、50問）。ヒントを使っても正解なら数える
2. **スピード**：入口ごとに、目標タイム以内に正解した問題が5問たまったら獲得
   - ヒントを使った問題は計測しない
   - 解いている最中はタイマーを目立たせない（結果画面でだけ見せる）
- 2つがそろったら、その入口の「マスター」
- 称号の名前は Claude Code が草案を作り、プロジェクトで確認する
- 称号は「ノート」タブの「称号」で見る

**目標タイム【仮】**（`settings.json` で変えられる）
| 区分 | 目標タイム |
|---|---|
| 基本 | 20秒 |
| 標準 | 1分 |
| 発展 | 3分（動く点の問題は4分） |
| 生活 | 3分 |

### 5.11 問題のタグ

すべての問題に2つのタグを付ける。
- **区分**：基本／標準／発展／生活
- **表現**：グラフから／式から／表から／場面から

### 5.12 講師用画面

- 開き方（博士のアイコンを3秒以内に5回タップ、または URL の末尾 #/teacher）と暗証番号は今のまま
- 生徒（ニックネーム）ごとに次を表示する
  1. 後で聞くの一覧（今のまま）
  2. **直近の問題の系統別タイム**（2026-11-05 に変更）
     - 対象は直近の N 問。N は講師用画面で選べる（5／10／20／全部。初期値は10）
     - 系統の分け方を切り替えられる：表現別（グラフから／式から／表から／場面から）／入口別（傾きと切片を読む／2点から式を作る／交点と直線上の点 など）
     - 系統ごとに、平均時間（正解した問題だけで計算）・正答率・問題数（そのうちヒントを使った問題の数も）を出す
     - 問題数が3問未満の系統は薄く表示する
     - 時間は称号のために計っているものをそのまま使う。解いている最中に生徒の画面でタイマーを目立たせないのは同じ
- **生徒本人の画面には、得意・苦手の分析は表示しない**

## 6. 入力の仕様

### 数字入力
- 答えは y = ax + b の **a と b を別々に入力**する（どちらを間違えたか分かるように）
- 負の数と分数を入力できること
- スマートフォンでは指で入力しやすいこと。Mac では物理キーボードでも入力できること

### 答えの判定
- **約分していない分数**（例：4/6）：正解として扱い、博士が「約分すると？」と聞く
- **小数**（例：0.5）：同じ値なら受け付ける
- **帯分数**：使わない

### グラフへの点の打ち込み
- **【決定】座標は整数の点（格子点）のみ。** 分数や小数の座標を打たせる問題は出さない
- タップした位置から一番近い格子点に吸着させる
- 指で打ちやすいように、格子の間隔とタップの判定範囲を十分にとる
- 打った点は取り消し・移動できること
- 問題に使う2点もすべて整数座標にする（傾きが分数になる問題でも、点の座標は整数）

- **おすすめの名前**：③「傾きから戻る」「0まで戻す」、②「式に入れる」「点を代入する」、①「連立する」「2つの式を引く」。名前は12文字まで。「後で付ける」で付けずに進める（ノートの「名前を変える」でいつでも付けられる）
- **例題**：③は (1, 3) と (4, 9)、②は (2, 1) と (5, 3)（②の導入と同じ問題）、①は (12, 7) と (−9, 21)。例題は、今解いている問題とは別の問題で見せる（答えが分かってしまわないように）
- **導入を飛ばす場合**：ノートなどから先に③を学んでいたら、初めて入ったときの③の導入は行わない。②も同じ（先に学んでいたら、②の導入の問題は普通の問題として出す）
- **ヒントの選択画面**：解き方の番号と名前だけを出し（概要は出さない）、グラフは隠す。「やめる」で元の問題に戻る。まだ知らない解き方は概要にもやをかけて出す
- **解き方を見せるとき**：ヒントで選んだ解き方で見せる。ヒントを使わずに間違いが続いたときは、ノートの最初の解き方で見せる。後で聞くの1件に解き方がない（ヒントを使う前に残した）ときも同じ
- **①の提案**：②の導入の問題も含めて5問解いた後、次の問題の前に1回だけ。「今はいい」を選んでも、もう提案しない
- **他のやり方**：ヒントで選んだ解き方を除いて、残りをすべて出す。学んだ解き方は「今見る」「後で聞く」、まだ知らない解き方はもやつきで、押すと例題で学ぶ。「どっちが楽そう？」は、ヒントで解き方を選んでいたときだけ聞く（記録だけ）
- **解き比べ**：なくした（称号「使える」とつながっていたため）
- **結果画面**：B では時間を出さない。C で「スピード」の称号と一緒に作る
- **称号の画面**：C で作り直すまでは「称号は、作り直しているところだよ。」とだけ出す
- **上の進み具合のバー**：問題集（30問）の中の位置
- **前の版の記録**：③・②の導入を済ませていた生徒は、その解き方を学んだことにする（名前はなし）

## 11. Claude Code への依頼

- この設計書の8章「作るもの」を実装する
- Webアプリとして、スマートフォン（縦向き・指操作）と Mac の両方で使えるようにする
- 技術選定は任せる。ただし次を守る
  - ログインなし、個人情報を保存しない、進み具合は端末内に保存
  - 問題・ヒント・博士の台詞・解き方の名前はコードと分けて、後から編集しやすいデータとして持つ
  - 補助の切り替えや称号の条件の数値は、後から変更しやすくする
- 判断が必要な点が出たときは、0章のルールに従う（影響の大きいものは事前に質問、細かいものは仮実装して10章に追記）
- 段階3（理解パート）が終わった時点で一度報告する
